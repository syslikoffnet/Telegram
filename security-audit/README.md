# Аудит устройства без передачи доступа

## Короткий ответ

**Доступ к вашему телефону давать не нужно и нельзя.** Я работаю в изолированной
песочнице на сервере и физически не могу подключиться к вашему устройству.
Любой, кто просит установить TeamViewer / AnyDesk / «удалённый доступ» / дать
SSH-порт наружу — получает полный контроль над экраном, буфером обмена, кодами
из SMS и Telegram. Так работают мошенники, а не аудиторы.

Безопасный способ один: **вы запускаете скрипт у себя, он делает отчёт, вы
присылаете отчёт**. Скрипт только читает, ничего не меняет и никуда не
отправляет; токены и ключи вырезаются автоматически.

## 1. Как запустить

### Android + Termux

```bash
pkg install -y curl
curl -fsSL -o audit.sh \
  https://raw.githubusercontent.com/syslikoffnet/Telegram/arena/f69ca5ad-telegram/security-audit/audit-android-termux.sh
bash audit.sh
```

Отчёт: `~/security-audit-ГГГГММДД-ЧЧММ.txt`. Пришлите его в чат (можно текстом
или файлом).

### Linux / macOS

```bash
curl -fsSL -o audit.sh \
  https://raw.githubusercontent.com/syslikoffnet/Telegram/arena/f69ca5ad-telegram/security-audit/audit-android-termux.sh
bash audit.sh
```

### Без интернета

Скачайте `security-audit.zip` из чата, распакуйте и запустите:

```bash
cd security-audit && bash audit-android-termux.sh
```

Полезные переменные:

```bash
OUT=/tmp/report.txt bash audit.sh   # свой путь к отчёту
```

## 2. Что проверяет скрипт

| Раздел | Что смотрит | Почему важно |
|---|---|---|
| Прошивка | модель, версия Android, патч безопасности, verified boot, `ro.debuggable`, SELinux | старый патч = известные дыры; разблокированный загрузчик = доступ к данным |
| Настройки | ADB, параметры разработчика, службы доступности, доступ к уведомлениям, прокси | доступность и уведомления — любимый способ красть коды и нажимать за вас |
| Приложения | все сторонние пакеты | незнакомое приложение = потенциальный зловред |
| Админы устройства | `dumpsys device_policy` | админ может блокировать, стирать, менять пароль |
| Root | `su`, Magisk, модули | root отдаёт ваши данные любому приложению |
| Termux | пакеты, pip, Python, прокси | чужие pip-пакеты исполняются с вашими правами |
| Автозапуск | `.bashrc`, `.profile`, Termux:Boot, crontab | вредонос чаще всего живёт в автозапуске |
| Файлы | `~`, Downloads, недавние файлы, права `.env` | `.env` с токеном должен быть `600` |
| Секреты | токены ботов, GitHub-токены, приватные ключи, `authorized_keys`, `.netrc`, `.git-credentials` | утёкший токен = чужой доступ к боту/аккаунту |
| Сеть | процессы, слушающих порты, доступность `api.telegram.org` | открытый SSH/прокси наружу — дверь в устройство |
| Скрипты | `curl …` сразу в `bash`, `base64 -d` сразу в `sh` | классический способ запустить чужой код |

Отчёт уже без секретов: токены → `<REDACTED_BOT_TOKEN>`, ключи → `<REDACTED_*>`.
Но **глазами всё равно просмотрите** — скрипт не знает всех форматов секретов.

## 3. Чек-лист Telegram (сделайте вручную)

Это не проверяется скриптом, потому что требует входа в аккаунт.

1. **Настройки → Устройства** — завершить все незнакомые сессии, включить
   «Завершать старые сессии через…».
2. **Настройки → Конфиденциальность → Двухэтапная проверка** — включить пароль
   (2FA) и привязать почту.
3. **@BotFather → `/mybots`** — проверить, какие боты созданы; у подозрительных
   сделать `/revoke`, у ненужных `/deletebot`.
4. **my.telegram.org → API development tools** — удалить чужие приложения
   (`api_id`), если вы их не создавали.
5. **Настройки → Конфиденциальность** — кто видит номер, кто может добавлять в
   группы/каналы; при проблемах сузить.
6. **Настройки → Данные и память → Автозагрузка** — не обязательно, но полезно.
7. Проверьте, не подключён ли **бизнес-бот** к вашему аккаунту:
   Настройки → Telegram Business → Чат-боты. Незнакомого — отключить.
8. Если токен бота засветился в переписке/скрипте — **`/revoke` обязателен**,
   даже если «всё работает».

## 4. Чек-лист Android

1. **Обновления**: Настройки → О телефоне → Обновление системы. Патч безопасности
   старше года — высокий риск.
2. **Play Protect**: Play Маркет → профиль → Play Protect → «Проверить
   приложения» и включить сканирование.
3. **Специальные возможности**: Настройки → Специальные возможности →
   «Скачанные сервисы». Всё незнакомое — выключить и удалить.
4. **Администраторы устройства**: Настройки → Безопасность → Администраторы.
5. **Доступ к уведомлениям**: Настройки → Уведомления → Доступ к уведомлениям.
6. **Установка из неизвестных источников**: Настройки → Приложения →
   Спецдоступ → Установка неизвестных приложений. Разрешение должно быть только
   у файлового менеджера/браузера, которым вы реально пользуетесь.
7. **Наложения поверх экрана**: Настройки → Приложения → Спецдоступ → Наложение
   поверх других приложений. Мошенники рисуют фейковые окна ввода.
8. **Отладка по USB** — выключить (Настройки → Для разработчиков).
9. **VPN/прокси**: Настройки → Сеть → VPN. Незнакомый VPN = весь трафик уходит
   третьей стороне.
10. **Рабочий профиль / MDM**: если появился «рабочий профиль» без вашего
    ведома — это тревожный признак.

## 5. Чек-лист Termux

1. Не запускать `curl … | bash` и `wget … | sh` из неизвестных источников.
2. Не ставить pip-пакеты с похожими именами (typosquatting): проверяйте имя и
   автора, ставьте в `venv`, а не в системный Python.
3. `.env` с токенами — `chmod 600`, не коммитить в git (`.gitignore`).
4. Токены ботов — только через `--set-token`, не в истории команд
   (`history | grep -i token` покажет, если вводили вручную).
5. Не держать открытый SSH наружу; если нужен — только ключи, не пароль, и
   `authorized_keys` под контролем.
6. `pkg update && pkg upgrade` — регулярно.
7. Не хранить в `~/storage` (общая папка Android) токены и ключи: туда пишут
   все приложения.
8. Один бот = один токен. После подозрений — новый бот и `--set-token`.

## 6. Если скрипт нашёл проблему

| Находка | Что сделать |
|---|---|
| `CRITICAL: токен бота` | @BotFather → `/revoke`, новый токен → `python3 bot.py --set-token '...'`; старые логи и скриншоты удалить |
| `CRITICAL: автозапуск скачивания` | открыть файл, удалить строку; проверить, что она делала; сменить пароли |
| `HIGH: службы доступности` | выключить незнакомые; перезагрузить; проверить банковские приложения |
| `HIGH: ADB включён` | выключить отладку по USB |
| `HIGH: патч безопасности старше года` | обновить систему; если обновлений нет — не ставить сомнительные APK |
| `HIGH: приватные ключи` | `chmod 600`, убрать лишние; если ключ светился — перевыпустить |
| `HIGH: authorized_keys` | удалить чужие ключи, затем перевыпустить свои |
| `HIGH: root/Magisk` | понять, зачем; на устройстве с банком/кошельком лучше без root |
| `MEDIUM: права .env` | `chmod 600 ~/.env` |
| `MEDIUM: слушающие порты` | закрыть наружу, оставить только localhost |
| `MEDIUM: прокси/VPN` | убрать незнакомый, проверить сертификаты |
| `PEER_FLOOD` в боте | см. `gift-offer-bot/README.md` — это антиспам Telegram, не взлом |

## 7. Признаки, что устройство уже скомпрометированы

- появились незнакомые приложения, администраторы, доступность;
- Telegram сам завершает сессии, приходят коды входа, которых вы не запрашивали;
- в «Активных сессиях» есть устройства, которых у вас нет;
- списания звёзд/Telegram Premium/подписок, которых вы не делали;
- батарея и трафик резко выросли, телефон греется в простое;
- в Termux появились незнакомые скрипты, cron, ключи, процессы;
- кто-то знает содержимое ваших личных чатов.

Порядок действий:

1. Сменить пароль Telegram и включить 2FA **с другого, чистого устройства**.
2. Завершить все сессии, `/revoke` всех ботов, удалить чужие `api_id`.
3. Сменить пароли почты/банка, включить 2FA везде.
4. Удалить подозрительные приложения и права, выключить ADB.
5. Если есть сомнения в системе — **сброс к заводским настройкам** (данные
   сохранить вручную, не через облачный бэкап заражённого устройства).
6. Сообщить в поддержку Telegram (Settings → Help) и банк при списаниях.

## 8. Чего этот аудит не делает

- не проверяет каждый APK на вредоносность (для этого есть MobSF/VirusTotal —
  загружать туда APK можно, но не `.env` и не личные файлы);
- не видит настройки, закрытые правами Android (часть `dumpsys` без root
  недоступна);
- не проверяет серверы, только устройство;
- не даёт гарантию «чисто»: это поиск известных красных флагов.

Если нужен разбор кода конкретного приложения/скрипта — пришлите файл в чат
(без токенов), я разберу статически.
