# Ключ подписи Pengram

Android ставит обновление поверх приложения только если **новый APK подписан тем же
ключом**, что и установленный. Отсюда два правила:

1. Бету и все следующие сборки подписываем **одним и тем же своим ключом**.
2. Ключ из репозитория (`TMessagesProj/config/release.keystore`, пароли `android/android`)
   для этого не годится: он известен каждому, кто видел исходники, и любой сможет
   выпустить «обновление» поверх вашей беты.

Поэтому сборка по тегу `build-*` **падает**, если секрета `KEYSTORE_BASE64` нет —
лучше провалившийся CI, чем бета, подписанная публичным ключом.

## Один раз: сделать свой ключ

Нужен JDK (`keytool`). На чистой Ubuntu: `sudo apt install openjdk-17-jdk-headless`.

```bash
bash scripts/new-keystore.sh
```

Скрипт спросит пароль, создаст `pengram-release.keystore`, покажет отпечаток
SHA-256 и положит рядом `pengram-release.keystore.base64`.

## Один раз: добавить секреты

GitHub → репозиторий → **Settings** → **Secrets and variables** → **Actions** →
**New repository secret**. Четыре штуки:

| Name | Значение |
|---|---|
| `KEYSTORE_BASE64` | содержимое `pengram-release.keystore.base64` одной строкой |
| `KEYSTORE_PASSWORD` | пароль, который вы придумали |
| `KEY_ALIAS` | `pengram` (если не меняли) |
| `KEY_PASSWORD` | тот же пароль |

После этого шаг «Prepare signing key» в логе скажет
«Используется пользовательский keystore из секретов».

## Хранение

- Сам файл `.keystore` — в менеджер паролей / офлайн-копия в двух местах.
- В репозиторий не коммитить (он уже подпадает под `.gitignore`-правила для ключей —
  проверьте перед `git add`).
- **Потеря ключа = конец линии обновлений.** Всем придётся удалять приложение и
  ставить заново, с потерей локальных данных Pengram.

## Как проверить готовый APK

```bash
"$ANDROID_HOME"/build-tools/*/apksigner verify --print-certs Pengram-standalone-arm64-v8a-runN.apk
```

Тот же шаг делает CI («Show signing fingerprint»): отпечаток SHA-256 печатается
в логе сборки, его удобно сверять от релиза к релизу.
