# Ключ подписи Pengram

Android ставит обновление поверх приложения только если **новый APK подписан тем же
ключом**, что и установленный. Отсюда два правила:

1. Бету и все следующие сборки подписываем **одним и тем же своим ключом**.
2. Тестовый ключ из репозитория (`TMessagesProj/config/release.keystore`, пароли
   `android/android`) для этого не годится: он известен каждому, кто видел исходники,
   и чужой человек сможет выпустить «обновление» поверх вашей беты.

## Ключ уже создан

Собственный ключ Pengram сгенерирован и лежит в репозитории **в зашифрованном виде**:

```
TMessagesProj/config/pengram-release.keystore.enc
```

| Что | Значение |
|---|---|
| формат | PKCS12, RSA-4096 |
| alias | `pengram` |
| действует до | 27 сентября 2056 года |
| отпечаток SHA-256 | `91:6D:72:54:5D:35:DE:AA:44:40:C7:77:60:EA:D4:E1:93:9A:69:6C:E5:CA:8F:2B:2D:43:8E:61:20:D6:71:87` |

Файл зашифрован AES-256 (PBKDF2, 400 000 итераций) тем же паролем, что стоит на самом
хранилище. Без пароля он бесполезен, поэтому его не страшно держать в репозитории —
и это заодно резервная копия ключа: пока цел репозиторий, ключ не потерян.

## Что нужно сделать один раз (хватит телефона)

Добавить **один секрет** — пароль. Браузер на телефоне, 5 шагов:

1. Откройте <https://github.com/syslikoffnet/Telegram/settings/secrets/actions>
   (если просит — войдите в GitHub).
2. Кнопка **New repository secret**.
3. **Name**: `KEYSTORE_PASSWORD` (латиницей, ровно так).
4. **Secret**: пароль от ключа — он выдан отдельным сообщением, скопируйте целиком.
5. **Add secret**.

Всё. Следующая сборка в логе напишет «Используется собственный ключ Pengram
(зашифрован в репозитории)», а APK будет подписан вашим ключом.

Проверить, что всё сработало: в логе сборки шаг **Show signing fingerprint** печатает
SHA-256 — он должен совпасть с отпечатком из таблицы выше.

## Пароль

- Сохраните его там, где не потеряете: «Избранное» в Telegram, менеджер паролей, бумажка.
- **Потеря пароля = потеря ключа** = обновления поверх беты ставиться перестанут,
  всем придётся удалять приложение и ставить заново.
- Пароль можно сменить: расшифровать `.enc` старым паролем, зашифровать новым, обновить
  секрет. Файл `scripts/new-keystore.sh` умеет делать и новый ключ с нуля (нужен ПК с JDK).

## Если захотите держать ключ не в репозитории

Тогда вместо `KEYSTORE_PASSWORD` заведите четыре секрета:

| Name | Значение |
|---|---|
| `KEYSTORE_BASE64` | хранилище, закодированное base64, одной строкой |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | `pengram` |
| `KEY_PASSWORD` | тот же пароль |

Этот путь имеет приоритет: если `KEYSTORE_BASE64` задан, зашифрованный файл не читается.

## Защита от случайной публикации без ключа

Сборка по тегу `build-*` (то есть публикация релиза) **падает**, если подписывать нечем:
нет ни `KEYSTORE_PASSWORD` с зашифрованным файлом, ни `KEYSTORE_BASE64`. Лучше красный CI,
чем бета, подписанная публичным тестовым ключом.
