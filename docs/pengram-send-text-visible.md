# Отправка: текст виден сразу, анимация сохранена

Дата: 2026-10-22 · ветка `arena/c8e4a10f-telegram` · третья итерация
(первая — `af2fa9c`, вторая — `71d1842`, см. `docs/pengram-send-animation-stock.md`)

## Требования пользователя, которые надо было совместить

1. «Отправленное сообщение стоит пустым, текст появляется позже» — так быть не
   должно, «вырвиглазно».
2. «Сейчас вовсе нет анимации отправки сообщений — откати к обычной
   телеграмовской отправке с её анимациями, но ничего не сломай».
3. После полного отката: «опять текст пропадает пока отправляется… 1 в 1 как и
   ранее».

То есть нужны оба свойства одновременно: анимация отправки **и** текст, видимый
с первого кадра. Полный откат к штатному поведению даёт первое ценой второго,
отключение overlay — второе ценой первого.

## Почему штатный морф даёт пустую строку

`ChatListItemAnimator.animateAddImpl` создаёт `TextMessageEnterTransition`, чей
`start()` взводит `ChatMessageCell.setEnterTransitionInProgress(true)`. Этот
флаг глушит у ячейки **не только текст** — в `ChatMessageCell` стоит
`!(enterTransitionInProgress && !currentMessageObject.isVoice())` на фоне
пузыря (:20990), времени (:20575), текстовых блоках (:21939, :23001), ответе
(:28384), превью ссылки (:14561), аудиозаголовке (:14891). Всё содержимое
строки на 250 мс (`ChatListItemAnimator.DEFAULT_DURATION`) переходит к overlay,
который рисует пузырь и текст с `alphaProgress = progress > 0.4f ? 1f :
progress / 0.4f` — то есть первые ~100 мс содержимое полупрозрачное, а в
crossfade-режиме текст назначения ещё и нарастает с тем же `alphaProgress`.

Важная деталь, снявшая прежнее подозрение на «залипание»: все ранние `return`
конструктора (`textLayoutBlocks` не готовы, `editField`/`layout` null, поле
ввода уже очищено — `TextUtils.isEmpty`) выполняются **до** создания `animator`,
а `start()` работает только при `animator != null`. Значит при bail-out флаг не
взводится и ячейка не прячется: пустая строка — это не сработавшая страховка, а
нормальный ход штатного морфа. Watchdog `DEFAULT_DURATION + 250` (500 мс) в этом
сценарии не участвует.

## Решение

`TextMessageEnterTransition` больше не владеет содержимым строки — только
анимацией. Введён флаг `DRAW_MESSAGE_CONTENT_IN_OVERLAY = false`:

| Что | Было (штатно) | Стало |
|---|---|---|
| `start()` | `messageView.setEnterTransitionInProgress(true)` — ячейка прятала весь пузырь | флаг не взводится: ячейка рисует себя сразу и полностью |
| Текст из поля ввода | летит в пузырь (`layout.draw`, `alpha = 1 - alphaProgress`) | не рисуется: вторая копия текста не нужна |
| Текст назначения (crossfade) | `drawMessageText(..., alphaProgress)` | не рисуется: его рисует ячейка |
| RTL-текст | рисуется overlay | не рисуется |
| Время, имя, кнопка комментария, подпись, реакции, ответ, превью ссылки | рисует overlay с `alphaProgress` | рисует ячейка |
| Ответ (`hasReply`) | блок ответа летел из панели | блок не рисуется |
| Форма пузыря | морф из поля ввода, `alpha = 255 * alphaProgress` | **сохранено** |
| Тень, «призрак» пузырька цвета поля ввода (`fromMessageDrawable`) | рисовались | **сохранены** |
| Затухание поля ввода (`editField.setAlpha(progress)`) | было | **сохранено** |
| Летящая кнопка отправки (`sendButton.draw`) | была | **сохранена** |
| Появление строки снизу (`translationY`, 250 мс) | штатное | **сохранено** (аниматор не тронут) |
| Перелёт голосового сообщения | `VoiceMessageEnterTransition` | **не тронут**, он по-прежнему взводит флаг сам |
| Досрочный финиш по `stableId`/`MessageObject`/поколению | был | **сохранён**: `enterGeneration` по-прежнему читается в `start()` |

Дополнительно: overlay и ячейка пользуют один и тот же `MessageDrawable`, а
`setBackgroundTopY` ячейка вызывает только при его пересоздании. Поскольку
строка теперь рисуется сама в том же кадре, после отрисовки пузыря overlay
возвращает drawable собственную геометрию — `messageView.setBackgroundTopY(true)`.
Иначе координата overlay (`container.getTop() - listView.getTop()`) осталась бы
в пузырьке строки.

Баланс `canvas.save()`/`saveLayerAlpha`/`restore()` в `onDraw` не изменился
(13 + 5 = 18, как и в базовой версии) — содержимое вырезано внутри своих пар.

## Что видит пользователь

Строка с сообщением появляется сразу полной — пузырь, текст, время — и выезжает
снизу за 250 мс. Одновременно из поля ввода прилетает форма пузыря с тенью и
«призраком» цвета поля ввода, проявляясь (`alphaProgress`) и садясь точно на
пузырь строки; кнопка отправки улетает, поле ввода гаснет и возвращается. К концу
перелёта обе формы совпадают, поэтому шва нет.

замером кадров; то, как выглядит летящая форма пузыря без текста внутри,
визуально не оценено.

## Откат

Одна правка: `DRAW_MESSAGE_CONTENT_IN_OVERLAY = true` в
`TextMessageEnterTransition` плюс вернуть
`messageView.setEnterTransitionInProgress(true)` в `start()` — это ровно штатное
поведение Telegram (с его пустой строкой на время перелёта). Вариант «без
анимации вовсе» — не создавать `TextMessageEnterTransition` в
`ChatListItemAnimator.animateAddImpl` (см. `af2fa9c`).
