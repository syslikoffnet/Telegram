# Отправка: текст виден сразу, overlay — как в официальном Telegram

Дата: 2026-10-22 · ветка `arena/c8e4a10f-telegram` · финальная схема

Итерации до этой: `af2fa9c` (overlay убран — пропала анимация), `71d1842`
(полный откат — пустой пузырь вернулся), `5cc832e` (overlay рисовал только форму
пузыря — пустая обводка накрывала строку), `65f3785` (быстрое проявление +
страховка от нулевого пузыря), `2ea9586` (ячейка не глушится + прижим цели),
`ce1df9b` (вычет U+200B в условии crossfade), `9f5c505` (копия строки в crossfade
непрозрачная). Последние три содержали костыли; здесь они удалены, причина
устранена в источнике.

## Требование

«Сообщение отправляется без текста, потом через время текст появляется»;
«если анимку от ТГ выключить — текст сразу нормально отправляется»;
«если включён жирный шрифт, ну отправка с любым шрифтом — появляется эта фигня»;
«раз через раз»; подсказки пользователя: «эффект жидкого стекла для панельки
ввода» и «ты правил верстку сообщений».

## Причина

Сверка с `DrKLO/Telegram` по blob SHA: `ChatListItemAnimator` и
`VoiceMessageEnterTransition` побайтово идентичны; методы перелёта в
`ChatActivityEnterView` не изменены; в `TextMessageEnterTransition` код
отрисовки идентичен (включая `drawBitmaps = false` — он постоянно выключен и в
официальном клиенте, то есть битмап-путь crossfade не работает ни у кого);
`ChatMessageCell.drawMessageText` отличается только форковыми фолбэками.

Ломают анимацию две вещи, обе — следствие штатной схемы «ячейка спрятана, строку
рисует overlay»:

1. **Мягкая вёрстка подменяет display-текст.** `MessageObject.pengramSoftWrap`
   расставляет невидимые U+200B в длинных словах и ссылках, чтобы текст не
   вылезал за границы пузыря на кастомных шрифтах, а `pengramGenerateLayout`
   объединяет display-текст с текстом layout
   (`messageText = pengramWrappedMessageText = textLayout.getText()`) — иначе
   разъезжаются диапазоны, ссылки и выделение. Штатное условие выбора ветви
   анимации `editText.length() != text.length() || containsSpans` после этого
   расходится по длине на число невидимых символов и включает **crossfade** на
   каждом сообщении с длинным словом или ссылкой. Отсюда «раз через раз»: зависит
   от текста сообщения, а не от настроек.
2. **Ячейка спрятана, а overlay рисует мимо.** `enterTransitionInProgress`
   глушит у строки фон, текст, время, просмотры, ответ и превью. В ветви
   crossfade копия строки проявляется через `alphaProgress` (при `alpha == 0`
   `drawMessageText` выходит без отрисовки — так и в официальном, и у нас), а
   цель перелёта считается через
   `getInputIslandHeightTarget()`, возвращающий фактическую высоту «острова»
   ввода, которую меняет жидкое стекло панельки. Любое расхождение — и на месте
   строки пустота, пока перелёт не закончится.

## Что сделано

`messenger/MessageObject.java` — один новый метод:

```java
public CharSequence pengramUnwrappedText() {
    return pengramOriginalMessageText != null ? pengramOriginalMessageText : messageText;
}
```

`ui/TextMessageEnterTransition.java` — две содержательные правки:

1. Текст для сравнения с полем ввода берётся из `pengramUnwrappedText()`, то есть
   без невидимых мест переноса. Условие crossfade осталось штатным
   (`editText.length() != text.length() || containsSpans`): мягкая вёрстка больше
   не переключает анимацию в другую ветвь, а настоящие расхождения (стили
   отправки, спаны, эмодзи) включают crossfade ровно как в официальном Telegram.
2. `start()` не вызывает `messageView.setEnterTransitionInProgress(true)`: строку
   рисует ячейка, overlay добавляет летящую копию поверх. Видимость текста,
   времени и просмотров больше не зависит от геометрии overlay. Это не новый
   режим для форка — гейт ячейки
   `!(enterTransitionInProgress && !currentMessageObject.isVoice())` означает,
   что голосовые перелёты всегда работали без глушения, и претензий к ним не было.

**Удалено как костыли:** вычет U+200B циклом в условии crossfade, прижим цели
перелёта к строке (`cellTop` + `dp(2)`), страховка от вырожденного прямоугольника
пузыря, константа `ALPHA_RAMP` и непрозрачная копия строки в crossfade.
Отрисовка overlay (пузырь, летящий текст, crossfade с проявлением через
`alphaProgress`, rtl, тень, призрак пузырька цвета поля ввода, летящая кнопка,
компенсация нижнего отступа списка) теперь совпадает с официальной.

Из отличий от официального `TextMessageEnterTransition` остались только
защитный жизненный цикл форка (поколения, `transitionFinished`,
`finishTransition()` из end/cancel/`onRemoved`, выход при уже очищенном поле
ввода) и эти две правки.

`ChatMessageCell`, `ChatListItemAnimator`, `MessageEnterTransitionContainer`,
`ChatActivityEnterView`, `PengramGlassSkin`, `ChatInputViewsContainer` не
изменялись: жидкое стекло панельки и мягкая вёрстка остались прежними.

## Цена

В середине перелёта видны и строка, и летящая копия (в официальном Telegram
строка на это время спрятана). К концу перелёта они совпадают, поэтому при
скрытии контейнера ничего не прыгает. Размен осознанный: четыре итерации с
сохранением штатного глушения давали пустое место.

  контракты (в `start()` нет глушения; источник текста — `pengramUnwrappedText()`;

сравнением скачанных через GitHub API файлов, а не запуском двух клиентов.
