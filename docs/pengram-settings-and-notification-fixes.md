# Фон, раздел набора текста, второе имя и переключатель «скрыть номер»

Дата: 2026-10-22 · ветка `arena/c8e4a10f-telegram`

Четыре замечания пользователя, каждое — отдельная причина в коде.

## 1. Фоновое уведомление путается с сообщениями

**Было.** Постоянное уведомление «держать приложение в фоне» брало иконку из
`PengramNotificationIcon.drawable()` — того же набора из пяти значков
(плоскость, пингвин, пузырь, колокольчик, звезда), который пользователь выбирает
для уведомлений **о сообщениях**. Заголовок и текст были эмодзи: `🐧✨` / `👀📡`
и `🐧💤` / `🌙☁️`. В шторке фоновая работа выглядела как сообщение: та же
иконка, а вместо слов — смайлики.

**Стало.**

- Новая иконка `res/drawable/pengram_notify_background.xml` — четырёхлучевая
  искра с малой искрой и точкой. Она намеренно **не входит** в набор
  `PengramNotificationIcon` (там пятиконечная звезда), то есть выбрать её для
  сообщений нельзя: две пометки различаются с первого взгляда. Монохромный
  белый контур, 24dp — требования статус-бара к small icon соблюдены.
- `NotificationsService` ставит её напрямую:
  `.setSmallIcon(R.drawable.pengram_notify_background)`. Иконка сообщений
  осталась выбираемой и не изменилась.
- Строки вместо эмодзи (ru/en):
  - `PengramBackgroundTitle` — «Pengram работает в фоне»
  - `PengramBackgroundText` — «Это не сообщение: связь активна, уведомления
    приходят»
  - `PengramBackgroundSleepTitle` — «Pengram в фоне: режим сна»
  - `PengramBackgroundSleepText` — «Это не сообщение: экономия батареи, связь
    проверяется реже»

Канал (`PengramBackgroundChannel`), тихий режим, `setOngoing`, приоритеты и
`foregroundServiceType` не тронуты — менялись только иконка и текст.

## 2. Раздел «Набор и отправка текста»: текст уезжал под поле и кнопки

**Причина.** Строка предпросмотра — кастомный `PengramTypingPreviewView`, чья
высота считается в `onMeasure` от измеренной подписи:
`params.topMargin = caption.getMeasuredHeight() + dp(6)`. Ширину для измерения
подписи брали как `MeasureSpec.getSize(widthSpec) - padding` без проверки
режима. Если сверху приходил не `EXACTLY` или нулевой размер (первый проход,
пересборка списка), подпись измерялась при ширине 0, переносилась по символам и
раздувала высоту строки; поле ввода с округлой рамкой (выглядит как кнопка)
уезжало вниз и накладывалось на соседние строки.

**Что изменено** (`ui/Components/PengramTypingPreviewView.java`):

- ширина берётся только достоверная: при режиме не `EXACTLY` или размере ≤ 0 —
  запасной вариант `getResources().getDisplayMetrics().widthPixels`, и spec
  приводится к `EXACTLY`. Подпись больше не может измериться при ширине 0;
- в конце `update()` добавлен `requestLayout()`: подпись меняется при
  переключении режима, переводе и крупном шрифте, а высота строки считается от
  неё — без пересчёта оставалась геометрия от прошлого текста.

Логика эффектов набора (`PengramTypingEffects`), их клип по границам поля,
курсор и пресеты не изменялись.

## 3. «Показывать официальное имя» не срабатывало

**Причина.** В шапке профиля два вида имени: `nameTextView[0]` — крупное имя в
раскрытой шапке, `nameTextView[1]` — имя в свёрнутой панели сверху; видимость
переключается альфой (`ProfileActivity:5601`, `:10222`, `:13020`). Жест
(`PengramOriginalName.attach`) был привязан **только к `[1]`**, а второй вариант
имени тоже ставился только в `[1]`. Профиль открывается с раскрытой шапкой, где
виден `[0]`, — поэтому нажатие и свайп по видимому имени не делали ничего.
Сам движок (`observe`, `other`, `canRefresh`, `refresh`, режимы
`MODE_TAP`/`MODE_SWIPE`/`MODE_BOTH`, проверка `tapEnabled()`/`swipeEnabled()`
внутри детектора) работал и не менялся.

**Что изменено** (`ui/ProfileActivity.java`):

- жест привязан к обоим видам имени (убран `if (a == 1)`);
- второй вариант имени ставится на оба вида — меняется тот, который виден;
- проверки `nameTextView[1] == null` заменены на `pengramHasNameView()`, чтобы
  обработчик не молчал, когда собран только один из видов.

Восстановление прежнего имени не менялось: `pengramHideOriginalName()` →
`updateProfileData(false)` пересобирает оба текста из объекта пользователя, как
и раньше; авто-скрытие через 6 секунд и защита от устаревших ответов
(`pengramNameCheckSeq`) сохранены.

**Название.** «Показывать официальное имя» → **«Второе имя жестом по имени»**
(en: «Second name on a gesture»). Прежнее название обещало постоянную замену
имени и слово «официальное», которого в функции нет; новое говорит, что это
второй известный вариант имени и что он показывается жестом. Подпись
(`PengramOriginalNameInfo`) уже объясняла источники и осталась без изменений.

## 4. «Скрыть мой номер» отключался после прокрутки

**Причина.** Строки-галочки биндятся из `UItem.checked`, зафиксированного при
постройке списка: `UniversalAdapter` вызывает
`checkCell.setTextAndCheck(item.text, item.checked, divider)`. Обработчик
`BTN_HIDE_PHONE` переключал `PengramConfig.toggleHidePhoneNumber()` и ставил
состояние на саму ячейку, но **не** обновлял `item.checked` и не пересобирал
список. Когда строка уходила за экран и возвращалась, адаптер заново биндил её
из устаревшего `item.checked` — переключатель показывал прежнее положение, хотя
в конфиге значение сохранилось.

**Что изменено** (`ui/PengramSettingsActivity.java`): в ветке `BTN_HIDE_PHONE`
добавлен `updateAll = true` — как у соседних переключателей этого экрана.
`updateAll` вызывает `listView.adapter.update(true)`, который заново выполняет
`fillItems` → `fillProfile` и пересоздаёт строку с
`.setChecked(PengramConfig.hidePhoneNumber)`, то есть из сохранённого значения.
Непосредственная установка состояния на ячейку оставлена — она даёт мгновенный
отклик до пересборки.
