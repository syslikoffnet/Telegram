# Анимация входа в чат и защита от чёрного кадра стекла

## Тумблер «Анимация входа в чат»

- **Где:** Настройки Pengram → «Эффекты и анимации» → строка с подписью
  (раздел раскрывается кнопкой «Показать ещё»), сразу под «Включить анимации».
- **Ключ:** `chatEnterAnim` (`PengramConfig.KEY_CHAT_ENTER_ANIM`).
- **По умолчанию: ВЫКЛ.** В выключенном состоянии переход полностью
  штатный (Telegram-овский выезд), новый код прочитывает тумблер каждый
  кадр — переключение действует без перезапуска.
- **Что делает при включении:**
  - открытие чата идёт в **длинном окне260 мс вместо штатных150** и с
    кривой `EASE_OUT_QUINT` вместо декелерата — кроссфейд, выезд на48dp
    и fade/scale чата идут в одном прогрессе, поэтому движение
    непрерывное и заметно более плавное;
  - экран проявляется (alpha 0.5→1) с лёгким зумом (scale 0.98→1),
    затухание закрытия (alpha 1→0.5, scale1→0.985);
  - только alpha/scale-свойства вдоль кадров перехода — без saveLayer,
    без битмап-оверлеев, без размытия, поэтому нет ни мерцаний, ни
    подлагиваний (дешёвые property-анимации);
  - сброс значений в `onTransitionAnimationEnd` (и при выключении
    тумблера на лету) — «залипших» полупрозрачных экранов не бывает;
  - режим превью (планшеты) анимация не трогает;
  - тумблер выключен → `BaseFragment.getFragmentTransitionDuration()`
    возвращает0 → ActionBarLayout идёт ровно по штатному пути:
    150 мс, декелерат, прежняя кривая — как в мастере.

Отложено (не в этой итерации): профиль, вложения и прочие экраны —
тумблер действует на открытие/закрытие чата.

## Чёрный кадр при входе в чат (починено в корне)

Симптом: ровно один кадр чёрной/тёмной вспышки в начале открытия чата
(на тёмных обоях заметнее). Причина: drawable стекла рисовался в первый
кадр, когда watcher ещё не захватил сцену — полупрозрачный фон
(`solveSrcColor`) и жидкая линза композитились по пустой заливке.

Фикс (безусловный, не завязан на тумблер):

- `BlurredBackgroundSource.hasContent()` — у источника спрашиваем,
  есть ли уже захваченное содержимое (RenderNode — `hasDisplayList()`
  с учётом underSource; Wrapped — делегат; Bitmap — валидный битмап;
  по умолчанию `true`);
- `BlurredBackgroundDrawableRenderNode.draw()` — пока содержимого нет и
  фон не непрозрачный, кадр не рисуется (прозрачно показывается сцена
  под экраном). Запись display list при этом уже сделана: как только
  источник наполнится, тот же список покажет содержимое без переигрыша.
- Влияет только на окно «сцена ещё не захвачена» — устоявшийся вид
  стекла (шапка, ввод, таб-бар) не меняется вовсе.
