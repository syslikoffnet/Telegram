# Где нажать, чтобы APK собирался

Сборке нужны два значения: `APP_ID` и `APP_HASH`. В коде их больше нет, они лежат
в секретах GitHub. Добавить — минута.

## По шагам

1. Открой репозиторий → **Settings** (шестерёнка, справа в меню репозитория —
   не в настройках аккаунта).
2. В левом списке: **Secrets and variables** → **Actions**.
   (Это не «Settings → Actions → General», там только разрешения. Нужен пункт
   именно **Secrets and variables**.)
3. Кнопка **New repository secret**.
4. Открывается форма из двух полей:

   | Поле | Что вводить |
   |---|---|
   | **Name** | `APP_ID` |
   | **Secret** | ваш api_id (число с my.telegram.org) |

   Серый текст `ВАШЕ_СЕКРЕТНОЕ_ИМЯ` в поле «Имя» — это подсказка, а не значение.
   Его не надо копировать: просто кликни в поле и набери `APP_ID` латиницей.
   Ошибка «Секретные имена могут содержать только буквенно-цифровые символы»
   появляется именно из-за русских букв в имени.

5. **Add secret**.
6. Ещё раз **New repository secret**, теперь:

   | Поле | Что вводить |
   |---|---|
   | **Name** | `APP_HASH` |
   | **Secret** | ваш api_hash (32 символа с my.telegram.org) |

Всё. Запускай сборку (**Actions → Build Pengram (Android arm64-v8a) → Run workflow**) —
шаг «Prepare API keys» станет зелёным.

## Необязательные секреты

| Name | Зачем |
|---|---|
| `SAFETYNET_KEY` | проверка SafetyNet при входе; пусто — просто не используется |
| `GOOGLE_AUTH_CLIENT_ID` | вход через Google; пусто — кнопка ничего не делает, приложение не падает |
| `KEYSTORE_PASSWORD` | пароль к собственному ключу подписи Pengram, см. `docs/KEYSTORE.md` |
| `KEYSTORE_BASE64`, `KEY_ALIAS`, `KEY_PASSWORD` | альтернатива: ключ целиком в секретах, а не зашифрованным файлом в репозитории |

## То же самое одной командой

Если под рукой есть `gh` (GitHub CLI) и ты залогинен:

```bash
gh secret set APP_ID   --body <ваш api_id>
gh secret set APP_HASH --body <ваш api_hash>
```

## Локальная сборка

Для сборки на своём компьютере секреты GitHub не нужны — там читается `api.properties`:

```bash
cp api.properties.example api.properties   # и вписать те же значения
./scripts/build-arm64.sh standalone
```

`api.properties` в `.gitignore`, в репозиторий он не попадёт.

## Важно про эти ключи

Сами значения в документации больше не хранятся — они живут только в секретах GitHub
(`APP_ID`, `APP_HASH`) и в локальном `api.properties`, который в `.gitignore`.

Старые значения успели побывать и в коде, и в этом файле, поэтому **они остались в истории
git**: `git log -p` их покажет. Пока репозиторий приватный, это не утечка. Перед любым
открытием исходников:

1. Заведите новую пару на <https://my.telegram.org>.
2. Поменяйте секреты `APP_ID` / `APP_HASH` — пересобирать и править код не нужно.
3. Старую пару можно просто бросить: привязки к приложению у неё нет.
