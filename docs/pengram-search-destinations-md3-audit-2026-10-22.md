# История переходов, MD3 и стеклянные поверхности — 2026-10-22

## Изменения

История поиска теперь содержит до восьми последних **достигнутых настроек**, а не введённые запросы. В JSON `settingsSearchDestinationsV1` записываются строковое имя ресурса, section и kind; числовые Android resource ID и локализованные названия не сохраняются. Повторный переход поднимает запись наверх. Чтение проверяет типы, размер, известность ключей и допустимость назначения, отбрасывая повреждённые элементы отдельно. Операции чтения/изменения истории синхронизированы.

Генератор проверяет имена по базовому XML и выпускает параллельные KEYS/HISTORY_ALLOWED и отдельные ключи родительских групп: 390 поисковых строк. Кнопки действий исключаются из истории; кнопки-редакторы значений (например, папка медиа) остаются допустимыми. Enter сам по себе ничего не сохраняет. Название, путь без Pengram/листа и иконка вычисляются при показе. История использует общий переход с обычной выдачей; запись производится после нахождения реальной строки/доступного родителя. Есть очистка всего списка и удаление одного элемента долгим нажатием с Bulletin.

Для MD3 поиска использован существующий FragmentSearchField внутри штатного контейнера ActionBar. Смена оформления сохраняет текущий текст. История получила тональные карточки; четыре режима редактора меню — тональные корзины, guarded-анимации 180 мс и подъём перетаскиваемой строки. Добавлена плавающая нижняя панель редактора меню. Тональные строки истории и карточки конструктора обновляются через общий канал подписок.

Стандартные BottomSheet-фоны переключаются обратимо с сохранением padding. Кастомные градиенты/обложки не заменяются: ChatMusic и плеер получают отдельную MD3-шапку с обратимыми цветами текста и значков. AI/DeviceName используют общий стандартный фон листа.

Новая выключенная по умолчанию настройка стеклянных поверхностей находится в существующем блоке оформления. Стекло применяется к шапке плеера только при наличии обложки и к нижней панели меню поверх списка. Захватывается отдельный источник без собственных контролов; используется существующий blur3. Liquid выбирается только после API 33+/LiteMode проверки, иначе остаётся blur. Для аппаратного canvas используется RenderNode, для программного — уменьшенный bitmap. Выключение/отсоединение возвращает прежний Drawable, снимает подписки и освобождает bitmap/display list. Общие параметры входят в подпись, обновления объединены в 80 мс. Новые поверхности имеют радиус 22 dp; sheen не анимируется при выключенных SharedConfig-анимациях.

ChatMusic имеет синтетический градиент, а не движущуюся обложку, поэтому линза там не добавлялась. QuickToggles и hero не получили фиктивное стекло без подходящего перекрывающегося источника. Пузыри сообщений, media viewer, полноэкранная обложка, редактор цитат и изображения/пингвин не изменялись.

Все новые строки есть в английском базовом и русском XML. API ID и api.properties не менялись.

## Однократная миграция

При отсутствии нового ключа старые строки `settingsSearchHistory` проверяются теми же queryTerms/relevance, что используются поиском. Переносится только единственный лучший допустимый результат с confidence >= 260; неоднозначные, неизвестные, слишком длинные и пустые запросы отбрасываются. Сравнение учитывает и недопустимые действия, чтобы они не уступали место случайной более слабой настройке. Новый JSON и удаление старого ключа выполняются одним Editor.apply. Наличие нового ключа предотвращает повторную миграцию даже при повреждённом новом значении. Сырые запросы в интерфейсе больше не показываются.
