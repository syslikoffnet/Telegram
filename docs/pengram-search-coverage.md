# Pengram settings search: coverage and navigation

- `scripts/gen-search-index.py` extracts settings rows, radio choices and labelled sliders from `PengramSettingsActivity.fill*` into `PengramSearchIndex.ITEMS`. Each entry records its actual section and closest group heading. 13 additional rows are explicitly inventoried on the dedicated chat-appearance and profile-history screens; search opens those real screens and highlights the relevant heading/row when visible.
- Current generated inventory: **401 rows** in 19 navigable section lists plus root links; the hidden penguin preferences are deliberately excluded (10 quick taps on the animated penguin are still required). This is an index of **actual listed controls**, not of every possible native Telegram preference or dynamic per-chat AI rule.
- `PengramSearchMetadata` provides a localized full path for every indexed row and per-row tags: title, own heading, path, own descriptive text when present and relevant RU/EN colloquial synonyms. Locale-scoped immutable search tokens avoid recomputing resource strings and regular expressions on every keystroke. Queries use normalized words and token prefixes. For example, “скрыть аву” targets avatar-related options; “радиус скругления” targets actual bubble/quote radius and chat-avatar shape controls. “Размер профиля” may find the **profile-history storage limit**, not an avatar-size control: no such profile-avatar-size setting was invented.
- Pengram's own search renders the complete multi-line breadcrumb beneath the row, with the destination and literal query occurrence emphasized. Telegram's global settings search also uses the same synonyms and an adaptive breadcrumb cell; selecting a result opens its owning screen and highlights a visible target. Search navigation temporarily expands collapsed Pengram blocks in the destination view; it does not persist a changed expansion preference.
- Conditional settings still depend on their parent option being enabled. When profile history is disabled, a query for a dependent control opens the profile-history screen and highlights its **enable** switch instead. Some dynamically named rows and other dedicated settings screens are not indexed; do not claim exhaustive coverage of all runtime controls.
