# Обновление Pengram на новые версии Telegram

Коротко: **да, это возможно, и переписывать ничего не придётся.** Один раз настраиваем связь
с оригинальным репозиторием, дальше каждое обновление — это две команды и разбор конфликтов
в тех файлах, где мы и Telegram правили одно и то же место.

Сейчас форк основан на коммите DrKLO/Telegram **`f2908b14` — «update to 12.10.6 (7112)»**,
то есть на самой свежей версии. Готовимся к будущим.

---

## Почему просто `git merge` сейчас не работает

Репозиторий форка создан «плоским» снимком: вся история Telegram в нём схлопнута в один коммит.
Общих предков с `DrKLO/Telegram` у него нет, поэтому git считает истории не связанными и
при merge пытается слить всё со всем — это тысячи конфликтов.

Чинится одной операцией: `git merge -s ours <базовый коммит Telegram>`. Она **не меняет ни одного
файла**, а только записывает в историю: «мы отпочковались вот отсюда». После этого git знает базу
и при следующем обновлении сравнивает только реальные изменения.

---

## Один раз

```bash
./scripts/upstream.sh setup
```

Скрипт подключит remote `upstream`, скачает историю Telegram (с `--filter=blob:none`, поэтому
без старых бинарников и в разы легче) и пришьёт базу. Содержимое рабочей копии не изменится —
проверяется `git status`.

Потом не забудь запушить: `git push origin <своя ветка>`.

## Каждое обновление

```bash
./scripts/upstream.sh check    # что вышло нового и где ждать конфликты
./scripts/upstream.sh update   # влить
```

`update` делает `git merge upstream/master`. Варианта два:

* **Конфликтов нет** — собираем APK, проверяем, коммитим. Всё.
* **Конфликты есть** — скрипт печатает список файлов. Разбираем по правилу ниже.

Откатиться в любой момент: `git merge --abort`.

---

## Как разбирать конфликты

1. **Файлы `Pengram*.java` не конфликтуют никогда** — Telegram про них не знает.
   Вся «начинка» форка (настройки, история удалёнок, плеер, пингвин, обход блокировок)
   живёт именно в них, поэтому обновление их не трогает.
2. Конфликтуют только «врезки» в файлы Telegram. Почти всегда правильное решение —
   **взять версию апстрима целиком и вернуть внутрь наши строки с `Pengram`**.
   Наши вставки легко узнать: они обращаются к `PengramConfig`, `PengramHistory` и т.п.
3. Если наш код вызывал метод Telegram, который в новой версии переименовали/изменил
   сигнатуру — правим вызов, логику не переписываем.
4. После merge обязательно:
   ```bash
   ./scripts/upstream.sh surface      # обновить список поверхности
   ./scripts/build-arm64.sh standalone
   ```
   и прогнать по приложению: настройки Pengram открываются, чат рисуется, удалёнки пишутся.

## Поверхность форка

Это список файлов Telegram, в которых есть наши правки — именно они и могут конфликтовать.
Актуальный список лежит в [`fork-surface.txt`](fork-surface.txt), пересобирается командой
`./scripts/upstream.sh surface`.

Сейчас это **175 файлов**, из них по-настоящему «тяжёлых» — единицы:

| файл | вхождений `Pengram` | чем рискуем |
|---|---|---|
| `res/values/strings.xml`, `res/values-ru/strings.xml` | 889 | почти не конфликтуют: наши строки идут отдельным блоком |
| `ui/ChatActivity.java` | 309 | главный кандидат на конфликты, Telegram правит его постоянно |
| `ui/ProfileActivity.java` | 169 | строка ID, дата регистрации, поиск по настройкам |
| `ui/Cells/ChatMessageCell.java` | 104 | метки удалённых, время поверх стикеров |
| `ui/DialogsActivity.java` | 99 | меню «три точки», вкладки, скрытие кнопок |
| `ui/Components/FragmentContextView.java` | 70 | плеер и строка песни |
| остальные ~170 файлов | 1–50 | обычно одна-две строки, конфликты редкие |

**Чем меньше поверхность — тем дешевле обновления.** Хорошая привычка: когда добавляешь фичу,
держи логику в своём `Pengram*.java`, а в файл Telegram вставляй одну строчку-вызов. Тогда даже
при конфликте видно, что вернуть.

## Что проверить после обновления Telegram

- `BuildVars.java` — апстрим мог вернуть свои `APP_ID`/`APP_HASH`/`CHECK_UPDATES`;
  у нас ключи берутся из `BuildConfig`, а `CHECK_UPDATES = false`.
- `TMessagesProj/build.gradle` — наш блок `buildConfigField APP_ID/APP_HASH` и задача `checkApiKeys`.
- `gradle.properties` — `APP_VERSION_NAME`/`APP_VERSION_CODE` приедут от Telegram, это нормально.
- Версии NDK/CMake в `build.gradle`: если апстрим их поднял — те же значения нужно поднять
  в `.github/workflows/build-android-arm64.yml` (`NDK_VERSION`, `CMAKE_VERSION`).
- `git submodule update --init --recursive` — Telegram регулярно двигает сабмодули.
