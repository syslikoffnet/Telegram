# Gift Offer Bot — сделки «подарок ↔ звёзды» 1:1

Бот-доска намерений: один человек показывает, что хочет **купить** подарок за N ⭐
или **продать** свой, второй принимает намерение — и **обе стороны получают точную
инструкцию**, как провести настоящую сделку встроенным в Telegram механизмом
**Offer to Buy**.

> **Главное:** бот не касса и не эскроу. Звёзды и подарки через него не проходят.
> Официальный оффер блокирует звёзды силами Telegram, при отказе или истечении
> они возвращаются покупателю. Бот берёт **0 %**.

---

## 1. Зачем это нужно

В Telegram уже есть безопасный обмен: покупатель открывает подарок → ⋮ →
**Offer to Buy** → указывает цену в звёздах. Telegram замораживает сумму, продавец
принимает оффер, и подарок с звёздами меняются атомарно. Если продавец отказался
или оффер истёк — звёзды возвращаются.

Проблема — найти вторую сторону и договориться о цене. Этот бот решает ровно две
задачи:

1. **витрина намерений** — «куплю за 500 ⭐», «продаю за 700 ⭐»;
2. **сведение сторон** — ссылка-приглашение на карточку и инструкции обеим
   сторонам в момент принятия.

Всё остальное делает Telegram. Поэтому бот не может «не выплатить», «забрать
подарок» или исчезнуть с деньгами: у него их нет.

## 2. Как проходит сделка (по шагам)

### Продавец

1. Открывает своего бота, отправляет:
   ```
   /sell https://t.me/nft/PlushPepe-123 500
   ```
   (`500` — цена в звёздах; ссылку берут у подарка: ⋮ → «Копировать ссылку»)
2. Команда **удаляется**, бот присылает **новое** сообщение — карточку и ссылку:
   ```
   https://t.me/<ваш_бот>?start=offer_7
   ```
3. Пересылает ссылку покупателю (в чат, в канал, куда угодно).

### Покупатель

4. Открывает ссылку → видит карточку → жмёт **«🤝 Принять намерение»**.
5. Бот сразу присылает ему инструкцию: открыть подарок → ⋮ → **Offer to Buy** →
   сумма **500 ⭐** → отправить.
6. Продавцу бот присылает свою инструкцию: **ничего не отправлять вручную**,
   дождаться оффера и принять его в клиенте.
7. Покупатель нажимает «📨 Я отправил оффер»; продавец принимает оффер в чате
   с подарком и нажимает «✅ Я принял оффер».

### Что делает Telegram

* замораживает звёзды покупателя на время оффера;
* передаёт подарок и звёзды одной операцией;
* возвращает звёзды при отказе или истечении срока оффера.

### Если передумали

* автор — `/cancel 7` или кнопка «✖️ Отменить»;
* вторая сторона — «❌ Отклонить»;
* через `OFFER_TTL_HOURS` (по умолчанию 24 ч) карточка сама станет «истёк».

## 3. Команды

| Команда | Что делает |
|---|---|
| `/offer <ссылка> <цена>` | «Хочу купить» — создаёт намерение |
| `/sell <ссылка> <цена>` | «Продаю» — создаёт лот |
| `/start offer_<id>` | Открыть карточку по ссылке-приглашению |
| `/myoffers` | Мои офферы и статусы |
| `/cancel <id>` | Отменить свой оффер |
| `/how` | Как проходит сделка 1:1 |
| `/help` | Список команд |
| `/id` | `chat_id` и `user_id` (для `BOARD_CHAT_ID`) |

Команда пользователя удаляется (`deleteMessage`, в бизнес-чате —
`deleteBusinessMessages`), ответ приходит **новым сообщением**. Редактируются
только карточки, которые отправил сам бот.

Статусы: `open` → `accepted` → `sent` → `completed`, а также `declined`,
`cancelled`, `expired`.

## 4. Установка в Termux (Android)

Нужны только Python 3.9+ и `ca-certificates`. Никаких `pip install` — бот
на стандартной библиотеке.

```bash
pkg update -y && pkg upgrade -y
pkg install -y python ca-certificates curl unzip

mkdir -p ~/gift-offer-bot && cd ~/gift-offer-bot
```

Дальше один из вариантов.

### Вариант A. Скрипт установки

```bash
curl -fsSL -o install-termux.sh \
  https://raw.githubusercontent.com/syslikoffnet/Telegram/arena/f69ca5ad-telegram/gift-offer-bot/install-termux.sh
bash install-termux.sh
```

### Вариант B. Вручную из архива

Скачайте `gift-offer-bot.zip` из чата, затем:

```bash
cd ~
unzip -o ~/storage/downloads/gift-offer-bot.zip
cd ~/gift-offer-bot
chmod +x run-tests.sh install-termux.sh
```

### Токен

Токен в сборке **пустой** — так и должно быть. Получите у [@BotFather](https://t.me/BotFather)
(`/newbot` или `/token`) и впишите одной командой:

```bash
cd ~/gift-offer-bot
python3 bot.py --set-token '123456789:AAH...'
```

Скрипт сам создаст `.env` с правами `600` и проверит токен через `getMe`.

### Проверка и запуск

```bash
python3 bot.py --check       # конфиг, база, getMe, webhook
python3 bot.py --selftest    # офлайн-сценарий 1:1, сеть не нужна
nohup python3 bot.py >> bot.log 2>&1 &
termux-wake-lock            # чтобы Android не усыпил процесс
```

Смотреть лог:

```bash
tail -f ~/gift-offer-bot/bot.log
```

Остановить:

```bash
pkill -f 'python3 bot.py'
```

Автозапуск после открытия Termux — добавьте в `~/.bashrc`:

```bash
pgrep -f 'python3 bot.py' > /dev/null || (cd ~/gift-offer-bot && nohup python3 bot.py >> bot.log 2>&1 &)
```

> В Termux `nohup` не спасает от агрессивного энергосбережения: включите
> `termux-wake-lock` и снимите ограничение батареи для Termux в настройках Android.

Systemd-юнит (`/etc/systemd/system/gift-offer-bot.service`):

```ini
[Unit]
Description=Gift Offer Bot (1:1 намерения)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=YOUR_USER
WorkingDirectory=/home/YOUR_USER/gift-offer-bot
ExecStart=/usr/bin/python3 /home/YOUR_USER/gift-offer-bot/bot.py
Restart=always
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now gift-offer-bot
journalctl -u gift-offer-bot -f
```

## 6. Настройки (`.env`)

Все ключи необязательны, кроме `BOT_TOKEN`. Значения по умолчанию — в скобках.

| Ключ | Смысл |
|---|---|
| `BOT_TOKEN` | токен от @BotFather (**обязателен**) |
| `API_BASE` | `https://api.telegram.org`; меняйте только для локального Bot API Server |
| `DB_PATH` | `offers.db` — база SQLite рядом с `bot.py` |
| `LOG_FILE` | `bot.log`; ротация 1 МБ × 3 |
| `LOG_LEVEL` | `INFO`, `DEBUG` для разбора проблем |
| `OFFER_TTL_HOURS` | `24` — через сколько намерение истекает |
| `MIN_PRICE` / `MAX_PRICE` | `1` / `1000000` — границы цены в звёздах |
| `MAX_OPEN_OFFERS` | `5` — активных офферов на пользователя |
| `CREATE_COOLDOWN_SECONDS` | `20` — пауза между созданиями |
| `BOARD_CHAT_ID` | `@channel` или `-100...` — публичная доска (бот должен быть админом) |
| `DELETE_COMMANDS` | `true` — удалять команды людей |
| `EDIT_CARDS` | `true` — обновлять свои карточки при смене статуса |
| `NOTIFY_ON_EXPIRE` | `true` — писать сторонам об истечении |
| `POLL_TIMEOUT` | `30` — long polling, 0…50 |
| `DRY_RUN` | `false` — ничего не отправлять, только лог |
| `INSECURE_TLS` | `false` — отключить проверку сертификата (только для отладки!) |
| `CA_BUNDLE` | путь к своему CA (корпоративный прокси) |
| `SUPPORT_CONTACT` | строка в `/help`, например `@my_support` |

Пример лежит в `env.example`.

### Публичная доска

1. Создайте канал, добавьте бота админом с правом публикации.
2. Узнайте id: отправьте в канал `/id` (или используйте `@username`).
3. Впишите `BOARD_CHAT_ID=@my_board` в `.env` и перезапустите.

На доске карточка обновляется при смене статуса, кнопка ведёт на deep-link
с намерением.

## 8. Ошибки и что делать

| Симптом | Причина и решение |
|---|---|
| `401 Unauthorized` | токен отозван/неверный. @BotFather → `/token` → `python3 bot.py --set-token '...'` |
| `409 Conflict` | запущено два экземпляра или остался webhook. `pkill -f 'python3 bot.py'`; бот сам снимает webhook при старте |
| `TLS EOF`, `сетевая ошибка`, `getaddrinfo failed` | нет интернета/блокировка. Проверьте `curl -sI https://api.telegram.org`; при необходимости `API_BASE` на свой прокси или `CA_BUNDLE` |
| `SSLError: certificate verify failed` | нет `ca-certificates` (`pkg install ca-certificates`) или кривой прокси. Временно `INSECURE_TLS=true`, но лучше починить сертификаты |
| `message to delete not found` | сообщение уже удалено — бот продолжает работу, это нормально |
| `message can't be deleted` | старше 48 ч, служебное сообщение или нет прав. В бизнес-чате нужно право «Delete Received Messages» |
| `message can't be edited` | бот правит только свои сообщения; карточка переотправляется новой |
| `not enough rights` | в канале/группе бот не админ; выдайте право удалять сообщения и публиковать |
| `bot was blocked by the user` | получатель заблокировал бота; уведомление пропущено, сделка не ломается |
| **`PEER_FLOOD`** | Telegram временно запретил боту писать в ЛС (антиспам). Бот больше **не пишет незнакомым**: уведомления идут только тем, кто нажимал `/start`, либо в бизнес-чат с `business_connection_id`. Ограничение снимается само за несколько часов; ускорить нельзя. Если бот «молчит» на новые ЛС — пусть человек нажмёт `/start` |
| `bot can't initiate conversation with a user` | человек ни разу не открывал бота. Отправьте ему ссылку `t.me/<бот>?start=offer_<id>` — после открытия бот сможет писать |
| Бот ограничен после старого использования | если аккаунт бота уже ловил `PEER_FLOOD` (например, его использовали для рассылок), надёжнее создать нового бота у @BotFather и вписать `--set-token` |
| `chat not found` | неверный `BOARD_CHAT_ID` или бот не добавлен в канал |
| `can't parse entities` | сломан HTML в имени/названии; сообщите пример, бот экранирует всё, что приходит от людей |
| `query is too old` | кнопка нажата после перезапуска бота — откройте карточку заново |
| `Too Many Requests: retry after N` | флуд-лимит; бот ждёт сам, при повторах увеличьте `CREATE_COOLDOWN_SECONDS` |
| `getMe` ок, но бот молчит | не снят webhook (бот снимает) или бот не был запущен в ЛС — отправьте `/start` |
| Бот не видит команду в бизнес-чате | не подключён business-бот или нет прав `can_read_messages` |

Проверка одной командой:

```bash
cd ~/gift-offer-bot && python3 bot.py --check
```

`--check` показывает токен маской, путь к базе, TTL, лимиты, `getMe` и наличие
webhook, а также подсказки к найденным проблемам.

## 9. Экономика и честность

* **Бот: 0 %.** Он не берёт и не может взять комиссию — не участвует в платеже.
* **Telegram:** при продаже подарка за звёзды берёт свою комиссию. Её нельзя
  обойти внутри Telegram; любые «обойдём комиссию через посредника» — красный флаг.
* Цена всегда в **звёздах** (⭐). TON и другие валюты бот не поддерживает.

## 10. Ограничения (важно прочитать)

1. **Бот не создаёт официальный оффер.** В Bot API такого метода нет: оффер
   отправляется только из клиента Telegram. Поэтому финальный шаг всегда делает
   человек в приложении.
2. **Бот не проверяет факт передачи.** Кнопки «Я отправил / Я принял» — это
   отметки сторон, а не подтверждение блокчейна. Гарантия — сам Telegram-оффер,
   который нельзя подделать.
3. **Нужен клиент с поддержкой Offer to Buy** (актуальный Telegram) и подарок,
   который можно продавать (не все подарки можно продать — Telegram сам покажет
   доступность кнопки).
4. **Репутация не проверяется.** Бот не знает, кто перед вами. Не выходите из
   Telegram, не отправляйте подарок «первым», не платите вне официального оффера.
5. **Бот не пишет первым.** Он отвечает на команды и уведомляет только тех, кто
   уже запускал его (`/start`). Иначе Telegram возвращает `PEER_FLOOD` или
   `bot can't initiate conversation` — это не баг бота, а антиспам Telegram.
6. **Оффер создаётся только в личке** (или в бизнес-чате, где бот подключён как
   business-бот). В группах и каналах команда отклоняется: сделка 1:1 не должна
   светить цену и инструкции в общем чате.
7. **Бизнес-чаты.** Если оффер создан в бизнес-чате, все сообщения по нему бот
   отправляет с `business_connection_id`. Без него Telegram отвечает
   `PEER_FLOOD`, даже когда `chat_id` выглядит как обычный пользователь.

## 11. Безопасность

* токен хранится только в `.env` с правами `600`, в логи и на экран не попадает
  (маска `12345678***op`);
* `.env`, `*.db`, `*.log` исключены из git;
* бот не принимает платежи и не хранит секреты пользователей;
* если токен засветился — @BotFather → `/revoke` → новый `--set-token`;
* в бизнес-аккаунте боту нужны минимальные права: читать сообщения, отвечать,
  удалять полученные. Без `can_delete_all_messages` команды останутся в чате.

## 13. FAQ

**Почему не эскроу?** Потому что в Bot API нет метода, который переводит звёзды
пользователю или удерживает их. Единственный механизм с блокировкой — нативный
оффер Telegram, и он работает только из клиента. Любой «эскроу-бот» обещает то,
чего API не умеет.

**А если продавец не примет оффер?** Звёзды вернутся покупателю по истечении
срока оффера (это делает Telegram).

**А если покупатель не отправит оффер?** Ничего не произойдёт: намерение истечёт
через `OFFER_TTL_HOURS`, звёзды никто не блокировал.

**Можно ли продавать за TON?** Нет, только звёзды.

**Сколько стоит?** Ноль. Хостинг — ваш (Termux на телефоне тоже подходит).
